# PRD — Агрегатор купонов на продукты (MVP)

**Дата:** 19 сентября 2026  
**Версия:** 1.0 (MVP)

---

## 1. Концепция

Специализированный агрегатор промокодов, купонов и скидок на **продукты питания, доставку еды и готовую еду** в России. Отличие от универсальных конкурентов — **узкая категория + максимальная достоверность** каждого предложения.

## 2. Целевая аудитория

- **Широкая аудитория** 18–55 лет
- Жители городов-миллионников (Москва, СПб, Екатеринбург, Казань и др.)
- Пользователи, регулярно заказывающие доставку продуктов/еды
- Экономные покупатели, ищущие скидки перед заказом

## 3. Состав MVP

### 3.1 Публичный сайт
- **Главная страница:** категории, популярные магазины, свежие купоны
- **Каталог магазинов:** список с фильтрацией по типу (доставка, фастфуд, рестораны, продукты)
- **Страница магазина:** логотип, описание, все активные купоны, ссылка на сайт
- **Карточка купона:** тип скидки, размер, условия, срок действия, кнопка «Показать код»
- **Показ кода + переход:** click_id/subid + открытие кода + редирект по CPA-ссылке
- **Поиск:** по магазину, категории, описанию купона
- **Адаптивность:** мобильная версия (mobile-first)

### 3.2 Telegram-канал
- Публичный канал с эксклюзивными и горящими предложениями
- Автопостинг новых купонов
- Прямые ссылки с click_id

### 3.3 Партнёрские CPA-сети
- Подключение Яндекс Еда, Kuper, ВкусВилл, Самокат, Пятёрочка
- Дальнейшее расширение по мере роста

### 3.4 Админ-панель (базовая)
- CRUD купонов и магазинов
- Модерация новых предложений
- Статусы купонов: `imported` → `pending_check` → `active`/`rejected`

## 4. Что НЕ входит в MVP

- Личные кабинеты пользователей (будет в v2)
- Кэшбэк-система
- Мобильное приложение (нативная разработка)
- Собственная партнёрская программа (только CPA-сети)
- Система отзывов и рейтингов

## 5. Модель монетизации

**CPA (Cost Per Action):**
- Партнёрская комиссия за каждый переход по купону/совершённую покупку
- На старте: 1–5% от заказа (зависит от партнёра)
- CPA-сети: прямое подключение к сервисам доставки + агрегаторы CPA

## 6. Пользовательские сценарии MVP

### Сценарий A: «Нашёл скидку на доставку»
1. Пользователь заходит на сайт
2. Видит на главной свежие купоны Яндекс Еды
3. Нажимает «Показать код» → видит промокод + кнопка перехода
4. Переходит на Яндекс Еду с click_id → применяет код → получает скидку
5. Мы получаем CPA-комиссию

### Сценарий B: «Ищет конкретный магазин»
1. Пользователь вводит «Купер» в поиске
2. Видит страницу Kuper со всеми активными купонами
3. Переходит по самому выгодному → CPA-транзакция

### Сценарий C: «Подписчик Telegram»
1. Пользователь подписывается на Telegram-канал
2. Получает ежедневные подборки горящих скидок
3. Переходит по ссылке → видит страницу с купоном → конвертируется

## 7. Критерии успеха MVP

| Метрика | Цель |
|---------|------|
| Уникальные посетители/мес | 10 000 |
| Клики по купонам | 500/мес |
| Конверсия в покупку | 3–5% |
| CPA-доход | Покрытие хостинга и обслуживания |
| Активных купонов | 100+ через 2 месяца |
| Подписчиков Telegram | 1000+ через 3 месяца |
| Достоверность кодов | >95% рабочих на момент проверки |

## 8. Стэк

- **Frontend:** Next.js (App Router) + TypeScript + Tailwind CSS
- **Backend:** Next.js API Routes
- **Database:** PostgreSQL (managed через publish/add-on)
- **Queue:** Redis / BullMQ для проверки и обновления купонов
- **Search:** OpenSearch (или простой полнотекстовый поиск в PostgreSQL для MVP)
- **Hosting:** Vercel / облако (опрелеляется на Этапе 1)
- **CDN:** Для статики
- **Telegram:** Bot API для автопостинга + click_id

## 9. Модель данных MVP (сущности)

```
Store — магазин/сервис
  - id, name, slug, logo, description, website, category, is_active

Category — категория магазина
  - id, name, slug

Coupon — промокод/купон/акция
  - id, store_id, title, description, code, discount_type, discount_value
    promo_url, click_id_template, starts_at, expires_at, status
  - status: imported | pending_check | duplicate | active | paused | expired | rejected | archived
  - priority: 1-10 (для сортировки)

Click — переход по купону
  - id, coupon_id, click_id, referrer, created_at
```
