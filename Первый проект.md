# Roadmap разработки агрегатора купонов

## Этап 0. Discovery и проектное основание

- [x] **PRD и границы MVP.** Зафиксированы аудитория, сценарии, состав MVP, монетизация (CPA), критерии успеха.
- [x] **Анализ конкурентов и SEO-спроса.** Собраны конкуренты, анализ ниши «продукты», подтверждение идеи.
- [ ] **Юридическая проработка.** Проверить оферты источников, правила парсинга, 152-ФЗ, cookie/согласия, рекламную маркировку и пользовательское соглашение.
- [x] **Модель данных и жизненный цикл купона.** Схема PostgreSQL, статусы: `imported` → `pending_check` → `duplicate`/`active`/`paused`/`expired`/`rejected`/`archived`.
- [x] **Backlog и архитектура.** 5 эпиков, ~30 задач, архитектура Next.js + PostgreSQL + Redis.

**Результат:** ✅ PRD, анализ рынка, модель данных, архитектура и backlog. Остаётся юридическая проработка.

## Этап 1. Архитектура и инфраструктура

- [ ] **Репозитории и CI/CD.** Настроить Next.js, TypeScript, Tailwind, линтеры, стиль кода, автоматические сборки и деплой в staging.
- [ ] **Базовая инфраструктура.** Подготовить PostgreSQL, Redis/BullMQ, объектное хранилище, managed add-on.
- [ ] **Конфигурация сред.** Разделить `dev/stage/prod`, настроить переменные окружения, безопасное хранение секретов.
- [ ] **Наблюдаемость.** Подключить структурированные логи, health checks, базовые алерты.
- [ ] **Безопасность и отказоустойчивость.** Настроить WAF/rate limit, резервное копирование, восстановление и rollback.

**Критерий готовности:** staging развёрнут автоматически, есть мониторинг, резервная копия успешно восстановлена, rollback отработан.

## Этап 2. Ядро данных и административная панель

- [ ] **Схема PostgreSQL.** Реализовать `stores`, `categories`, `coupons`, `sources`, `clicks`, `audit_log` и связи между ними.
- [ ] **История изменений.** Сохранять источник каждого купона, версию данных, время импорта, автора и причину изменения статуса.
- [ ] **Админка и роли.** Создать аутентификацию, базовые роли и разделение доступа.
- [ ] **CRUD магазинов и купонов.** Реализовать создание, редактирование, фильтрацию, массовые операции и предпросмотр.
- [ ] **Аудит и журналирование.** Фиксировать все значимые действия.
- [ ] **Очередь модерации.** Выводить новые и сомнительные купоны с причиной попадания в очередь.

**Критерий готовности:** все сущности доступны через API и админку, права проверены, изменения сохраняются в audit log.

## Этап 3. Публичный MVP

- [ ] **Главная страница.** Показать категории, популярные магазины, свежие и проверенные купоны.
- [ ] **Каталог магазинов.** Реализовать категории, фильтры, сортировку и пагинацию.
- [ ] **Страница магазина.** Вывести описание, логотип, условия, активные купоны и похожие магазины.
- [ ] **Карточка купона.** Показать тип предложения, размер скидки, условия, срок действия и кнопку получения кода.
- [ ] **Показ кода и переход.** Генерировать уникальный `click_id/subid`, открывать код и перенаправлять по партнёрской ссылке.
- [ ] **Поиск и фильтры.** Реализовать поиск по магазину, категории, описанию и типу предложения.
- [ ] **Адаптивность и доступность.** Проверить мобильную версию, клавиатурную навигацию, семантическую вёрстку.
- [ ] **Telegram-канал.** Настроить бота, автопостинг свежих купонов с click_id.

**Критерий готовности:** все страницы работают, поиск выводит результаты, click-трекинг записывается, Telegram публикует посты.
